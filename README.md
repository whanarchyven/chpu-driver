# cnc-erp

Очередь программ для фрезера Velber. Программу загружают в браузере, ноутбук сам кладёт её в память стойки, оператор на пульте станка нажимает «Старт», а браузер показывает строку программы, тревоги и готовые детали.

Подробности: [docs/ВНЕДРЕНИЕ.md](docs/ВНЕДРЕНИЕ.md), [docs/API.md](docs/API.md), [docs/HANDOFF.md](docs/HANDOFF.md).

## Где что работает

Завтра участвуют три вещи. Ноутбук один: на нём и очередь, и связь со станком.

| | Что это | Что там запущено |
|---|---|---|
| **Стойка** | Экран и пульт на самом станке, Syntec, Windows CE | Ничего нашего. Там только меню стойки: адрес и пункт Core server. «Старт» нажимают на этом пульте |
| **Ноутбук** | Windows 11 рядом со станком, соединён со стойкой кабелем | Три вещи: сервер очереди (`Запустить-сервер.cmd`), страница в браузере, агент (ставится с флешки и дальше работает сам) |
| **Флешка** | Папка `CncAgent` | Только установка и две кнопки проверки. После установки флешку можно вынуть |

Адреса в кабеле между ноутбуком и стойкой, без интернета:

| | Адрес |
|---|---|
| Ноутбук | 192.168.50.1 |
| Стойка | 192.168.50.20 |

Страница очереди: `http://192.168.50.1:5174`. Вверху три пункта: **Очередь**, **Программы**, **Станки**.

## Сегодня вечером, дома, ноутбук в интернете

Флешку собирают не на ноутбуке. На компьютере, где уже лежит проект, скопировать на флешку папку целиком:

`cnc-erp\agent\usb\CncAgent`

На ноутбуке:

1. Поставить [Docker Desktop](https://www.docker.com/products/docker-desktop/). После установки в трее у кита должно быть «Engine running». Если попросит перезагрузку и виртуализацию — сделать. Поставить [Node.js 20](https://nodejs.org/) и [Git](https://git-scm.com/).
2. Открыть командную строку (Win+R, `cmd`) и выполнить:

   ```bat
   git clone https://github.com/whanarchyven/chpu-driver.git
   cd chpu-driver
   npm ci
   set SERVER_IP=192.168.50.1
   Запустить-сервер.cmd
   ```

3. Дождаться в этом окне строк «Веб» и «Ключ агента». Ключ пока `cnc-stand-dev`, записать его. Окно можно закрыть. Остановить сервер, если мешает: `docker compose -f server\docker-compose.yml down`.

Адрес `192.168.50.1` задаётся уже дома: страница собирается с ним, а у станка интернета не будет.

## Завтра у станка

Кабель — обычный, переходник не нужен. Один конец в разъём Ethernet на ноутбуке, другой в разъём Ethernet на стойке. Раздачу интернета с ноутбука не включать. В поле «Основной шлюз» на этом кабеле ничего не писать.

### 1. Стойка: адрес и доступ для ноутбука

Станок остановлен. На экране стойки:

1. Открыть сеть. В русском меню это «Обслуживание» → «Сеть». На английском экране той же стойки: Maintain (F5) → Network (F2).
2. Задать IP `192.168.50.20`, маску `255.255.255.0`, шлюз оставить пустым.
3. В том же разделе сети найти **Core server** (может называться Remote или Core Server). Включить его, поставить запуск вместе со стойкой и нажать «Запустить». Если меню спрашивает пароль обслуживания — он нужен на этом шаге. После этого стойка принимает ноутбук.
4. Выключить и включить стойку. Core server должен подняться сам.
5. На пульте выбрать режим **Авто**. Пока стойка в ручном или MDI, ноутбук положит файл, но основной программой его не сделает.

### 2. Ноутбук: адрес кабеля

Параметры → Сеть и Интернет → Ethernet → имя адаптера → «Назначение IP-адреса» → Изменить → Вручную, IPv4 включить:

| Поле | Значение |
|---|---|
| IP-адрес | 192.168.50.1 |
| Маска подсети | 255.255.255.0 |
| Шлюз | пусто |
| DNS | пусто |

Win+R → `cmd` → `ping 192.168.50.20`. Пошли ответы — кабель живой.

### 3. Ноутбук: сервер очереди

В трее кит Docker должен быть «Engine running». В папке проекта (`chpu-driver`):

```bat
set SERVER_IP=192.168.50.1
Запустить-сервер.cmd
```

Если вчера файл `server\.env` записался с другим адресом, удалить его и запустить команду ещё раз. Окно не закрывать. В браузере ноутбука открыть `http://192.168.50.1:5174` — должна открыться «Очередь ЧПУ».

### 4. Ноутбук: агент с флешки

На флешке двойной щелчок по **Установить.cmd**, согласиться на запрос администратора. Windows 11 уже содержит нужный .NET, установщик сам добавит библиотеку Visual C++.

| Вопрос в окне | Что ответить |
|---|---|
| IP-адрес сервера очереди | 192.168.50.1 |
| IP-адрес стойки ЧПУ | 192.168.50.20 |
| Ключ агента | `cnc-stand-dev` (или тот, что напечатал сервер) |
| Имя станка | velber-1 |

Дальше агент работает сам, в трее его нет. Флешку можно вынуть.

### 5. Проверка, что ноутбук видит стойку

Снова флешка, двойной щелчок:

1. **Проверить-стойку.cmd.** В окне: «Связь есть», ПО 10.118, «библиотека syntec-10.118», режим, состояние, имя программы.
2. **Проверить-передачу.cmd.** В окне: «ПЕРЕДАН через Remote API. В списке программ стойки: есть». Файл `ERP-TEST.CNC` станок не двигает.

В браузере пункт **Станки**: карточка `velber-1`, зелёная точка, «связь есть», режим «Авто», состояние «Готов». Кнопка «Файлы на стойке» показывает `ERP-TEST.CNC`.

### 6. Проверка очереди

В браузере:

1. **Программы** → «Выбрать файлы» → на флешке `ERP-TEST.CNC`. Под кнопкой появится «ERP-TEST.CNC: добавлен».
2. В списке программ справа поле количества оставить `1`. Над таблицей список «станок» переключить с «любой» на `velber-1` (пункт появляется, когда карточка станка уже зелёная). Нажать **+** в строке файла.
3. **Очередь.** Строка задачи проходит сама: «в очереди» → «файл на стойке» → «выбрана на стойке». На экране стойки в имени основной программы — `ERP-TEST.CNC`. Обычно это несколько секунд.

Дальше на пульте станка, без заготовки или с поднятым Z:

| Куда нажать | Что видно в браузере, пункт «Очередь» |
|---|---|
| Зелёная кнопка «Старт» на пульте | «фрезеруется», на вкладке «Станки» растёт номер строки |
| «Сброс» (Reset) посередине настоящей программы | снова «выбрана на стойке», деталь не прибавляется |
| «Старт» и дождаться конца программы (M30) | «готово», счётчик деталей увеличился |

`ERP-TEST.CNC` заканчивается сразу, на ней проверяется сам путь: старт дошёл, деталь засчиталась. Потом то же самое короткой рабочей программой с поднятым Z.

На странице задачи (щелчок по номеру в очереди) кнопки «+1 деталь вручную» и «−1» поправляют счётчик, если деталь испорчена.

## Если на экране не то

| Что видно | Куда смотреть |
|---|---|
| `ping` молчит | кабель, адрес на стойке, на ноутбуке шлюз пустой |
| «стойка не отвечает», порт 5566 закрыт | на стойке Core server выключен или не поднялся после включения |
| Проверить-стойку: «SocketError (-16)» | на флешке нет папки `agent\syntec-10.118`, скопировать `usb\CncAgent` заново |
| Очередь остаётся «файл на стойке» и не становится «выбрана на стойке» | на пульте режим не «Авто» или станок не в покое |
| В списке «станок» нет `velber-1` | агент не запущен или сервер открыт не с `192.168.50.1`. Карточка на вкладке «Станки» покажет текст ошибки |
| Страница `http://192.168.50.1:5174` не открывается | в трее Docker «Engine running», окно `Запустить-сервер.cmd` без ошибки, в `server\.env` адрес `192.168.50.1` |
| Пункта Core server в меню нет | сфотографировать «Обслуживание → Сеть». Без этого пункта ноутбук состояние станка не прочитает |

Журнал агента на ноутбуке: `C:\Program Files (x86)\CncAgent\cnc-agent.log`. Те же последние строки видны внизу карточки на вкладке «Станки».
